# Протокол исполнителя доски

Тебя запустила локальная доска задач. В запуске указаны номер `ID`, заголовок и описание задачи. Весь ход работы и результат ты отдаёшь через pull request: доска читает его с GitHub.

## Шаги

1. Ветка `claude/task-ID` от `origin/staging` (облако может дописать к имени хвост, это нормально). Сразу сделай пустой коммит, запушь и открой **draft PR** в `staging` с заголовком `[#ID] суть задачи`.
2. Тело PR начни с раздела `## Ход работы` и обновляй его через `gh pr edit --body-file` на каждом этапе (прочитал код, план, реализация, тесты, пуш). Короткие строки с отметкой этапа, новые строки добавляй вниз. Это единственный «лог», который видит человек, пока ты работаешь.
3. Сделай задачу по правилам из `CLAUDE.md`. Новое поведение закрывай тестом в `tests/`.
4. `npm ci && npm test`. Красные тесты чини; не удаляй и не ослабляй чужие тесты, чтобы они прошли.
5. Закоммить и запушь. Перепиши тело PR: первой строкой `## Отчёт`, второй `Модель: …` (как ты определяешь себя сам: нужно, чтобы сравнивать результаты по моделям), затем что сделано, какие файлы изменены, какие тесты запускались и чем кончились, что не удалось или сомнительно. Раздел `## Ход работы` оставь ниже. Потом `gh pr ready`.

## Если не получилось

Начни тело PR со строки `## Отчёт` и строки `СБОЙ: причина`, PR оставь draft. Не оставляй работу молча.

## Доработка

Приходит сообщением в эту же сессию. Верни PR в draft (`gh pr ready --undo`), поправь, снова прогони тесты, обнови `## Отчёт`, снова `gh pr ready`.

## Если gh недоступен

В облаке `gh` может быть не авторизован: тогда веди PR через GitHub MCP-инструменты сессии. Результат тот же: draft-PR, ход работы, отчёт, ready.

## Запреты

- Не пушь в `main` и `staging`, не мерджи PR: это решение человека на доске.
- Не меняй `.github/` и `.agent/`.
- Не печатай и не коммить секреты.
