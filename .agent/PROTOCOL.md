# Протокол исполнителя доски

Тебя запустила доска задач. В запуске указаны номер задачи `N` и твой движок `ENGINE` (`claude` или `hermes`). Работай только по этому протоколу, одинаково для любого движка.

## Шаги

1. Прочитай задачу вместе с комментариями: `gh issue view N --comments`. Комментарии, начинающиеся с «Доработка:», важнее исходного текста.
2. Ветка называется `ENGINE/issue-N`. Если она есть на origin, продолжай её (это доработка), иначе создай от `origin/staging`.
3. Сделай задачу. Правила сайта в `CLAUDE.md`. Новое поведение закрывай тестом в `tests/`.
4. Запусти `npm ci && npm test`. Красные тесты чини; не удаляй и не ослабляй чужие тесты, чтобы они прошли.
5. Закоммить, запушь ветку и открой PR в `staging` (или обнови существующий). В заголовке PR `#N` и суть, в теле `Closes #N` не пиши: закрывает задачу доска.
6. Оставь в задаче комментарий-отчёт, который начинается строкой `## Отчёт` и содержит: что сделано; какие файлы изменены; какие тесты запускались и чем кончились; что не удалось или сомнительно. Ссылку на бету не пиши: её добавит автоматика после сборки.
7. Переведи статус: `gh issue edit N --remove-label st:running --add-label st:review`.

## Если не получилось

Оставь комментарий `## Отчёт` с причиной, затем `gh issue edit N --remove-label st:running --add-label st:failed`. Не оставляй задачу в `st:running`.

## Запреты

- Не пушь в `main` и `staging`, не мерджи PR: это решение человека на доске.
- Не меняй `.github/` и `.agent/`.
- Не печатай и не коммить секреты.
